# 交行 2104 通知接入指引

适用订单结果、实际核销、作废完成三类出站通知。代码实现与离线验证不代表真实银行验收。协议以交行接入包与两份主设计「交行 2104 通知实施细化」为准。

## 构建与数据库

使用 JDK21/Maven3.9+，在构建机器先运行：

```sh
bash scripts/install-bocom-sdk.sh '/path/to/bank-distribution'
mvn clean package
mvn -f cardshop-trade-engine-simulator/pom.xml test
python3 -m unittest discover -s scripts/tests -p 'test_*bocom*.py'
```

也可向安装脚本传入官方JAR。脚本核验固定SHA-256，再安装`com.bocom:bocom-openapi-sdk:2.2.6`及受管依赖POM；该私有制品不声称在Maven Central可用，不提交银行二进制、示例密钥或个人绝对路径。CI需预安装同一制品或使用组织受控制品库。

部署前通过既有Liquibase流程追加`0024-bocom-notify-route-and-attempt`。它增加任务的投递通道、路由快照、银行编码正文、领取代次，以及`recharge_notify_attempt`。历史任务默认`DIRECT_JSON`，不迁移为银行任务。回滚应用保留可靠任务与审计，不删除列/表。存在旧Worker时须停发、等待在途请求结束并统一节点版本，避免旧节点绕过新租约回写合同；先在dev/test执行，不直接用于生产放行。

## 配置示例

以下为配置结构，所有实际参数由银行/部署系统提供。不要复制SDK示例中的appId、protocol、密钥或地址。商户编码示例为`A35`，注册与发送开关相互独立。

```yaml
trade:
  engine:
    notify:
      claim-lease-seconds: 60
      retry-backoff-seconds: 30
      bocom:
        enabled: false
        tls-trust-certificate-path: ${BOCOM_TLS_TRUST_CERTIFICATE_PATH}
        connect-timeout-ms: 3000
        read-timeout-ms: 3000
        merchants:
          A35:
            route-version: route-v1
            gateway-url: ${BOCOM_2104_GATEWAY_URL}
            protocol: ${BOCOM_A35_PROTOCOL}
            app-id: ${BOCOM_APP_ID}
            signature-algorithm: RSA
            private-key-ref: a35-private-v1
            bank-public-key-ref: a35-bank-v1
        credentials:
          a35-private-v1:
            org-code: A35
            app-id: ${BOCOM_APP_ID}
            signature-algorithm: RSA
            private-key: ${BOCOM_PRIVATE_KEY}
          a35-bank-v1:
            org-code: A35
            app-id: ${BOCOM_APP_ID}
            signature-algorithm: RSA
            bank-public-key: ${BOCOM_PUBLIC_KEY}
```

`gateway-url`必须为可信HTTPS完整路径`/api/trade/J_IEP_001_2104/v1`。`protocol`必填且最多200字符，同商户三类通知共用。银行发送默认关闭；关闭后仍生成银行任务，等待恢复，不回退到商户提供的URL。银行商户路由不完整会保留原Outbox/核销事件等待恢复。

RSA采用SDK要求的PKCS8私钥和X.509公钥Base64；SM2配置算法为SM2、使用官方生成的十六进制密钥。商户请求使用的signKey与银行签名私钥完全独立。凭据引用视为不可变版本，轮换新增引用并保留历史引用直到存量任务处理完成，不覆盖同名版本。

TLS信任文件是经核验的X.509证书，与银行报文验签公钥不同，不能用`.pub`替代。工厂先执行官方`openCertVerify`，同一JVM只允许一个信任锚；初始化失败禁止发送，不调用`ignoreSSLHostnameVerifier`。SDK原HTTP会对307/308转投原form，因此专用子类保留SDK构造/签验，仅以严格JDK21 HTTP替换传输，禁止重定向、强制TLS1.2/主机名检查并为完整响应设总期限。证书变化统一停发/重启，不按商户或请求动态切换信任。

## 通知和恢复规则

- 首次任务保存结构化事实及`trx_data_imprt`编码，后者为`key:value,key:value`文本而非JSON。值不能含逗号，时间中的冒号保留，最大2500 Unicode码点，不截断。空值保留`key:`。
- `operate_type=1`订单结果，包括成功和失败；`2`实际核销；`3`作废完成。名创核销为3/2，作废为3/3。作废不能生成订单失败通知。
- 银行通知不含业务sign/keyId，不要求下单notify_url非空。金额为整数分，核销/作废保留原事实时间。网关认证由官方SDK执行。
- 正常重试保持任务ID、正文、timestamp、nonce、protocol和路由不变；每次实际请求使用新msg_id，审计保存ref_msg_id。新msg_id不代表银行业务不会重复，业务幂等须在银行联调确认。
- 响应通过SDK验签且biz_state=S、body.code=200才成功。数字和字符串200都支持；HTTP200、isSuccess()单独为真均不足以确认。
- 配置关闭、历史凭据版本缺失、TLS初始化失败时暂缓，不消耗物理请求重试次数；网络或未确认结果退避重试，验签失败及确定性任务错误转人工。请求登记失败不发送，完成审计失败转人工保留证据。
- 所有任务结果以领取持有者、状态、claim_version和有效租约CAS回写；旧Worker只能完成自己的尝试记录，不能修改新租约任务。总HTTP预算必须小于剩余租约。
- 只使用项目脱敏且限频的异常日志。SDK日志可能输出完整请求/响应，bootstrap日志配置已关闭com.bocom.api及HTTP wire/header日志，禁止调试时重新打开原文日志。

## 离线示例与验收

```sh
python3 scripts/bocom-2104-example.py --operation order
python3 scripts/bocom-2104-example.py --operation redeemed
python3 scripts/bocom-2104-example.py --operation cancelled
```

命令仅生成合成JSON包装，不读取密钥、不发送网络请求，不能把示例协议号当作实际环境值。

独立银行网关桩位于simulator的`bocom`包，仅使用loopback与运行时测试密钥，测试form、网关签名、业务字段解码、响应签名、请求关联及合成事件去重。它与旧A39直连回调接收器分开，不能把后者当作银行网关桩。基础设施HTTPS集成测试覆盖实际准备/签名/发送/验签与三类业务ACK。

真实dev/test联调前确认银行实际网关、appId、protocol、算法、出口白名单、双方签验公钥及TLS证书来源；按显式测试商户启用，验证三类通知、重复通知、响应丢失与人工恢复。名创共享核销入口的改造不在本次银行传输范围内；实际核销端到端仍需先打通可信供应商事件入口。执行过程及证据统一记录`docs/集成测试.md`，本指引不提供生产放行依据。
