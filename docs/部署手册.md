## 2. 安全和密钥约定

| 项目 | 开发/测试环境 | 生产环境 |
| --- | --- | --- |
| 明文密钥落盘 | 禁止写入 Git、Markdown、日志、启动脚本和 JVM 参数 |  |
| 密钥来源 | 运维密钥、部署平台变量、本机忽略文件 `config/.dev.env` 或 Nacos 加密配置 |  |
| `.env` 加载方式 | `bin/start.sh` 通过 Bash `source` 加载 `config/.dev.env` |  |
| `.env` 引号规则 | 密码、JWT secret、API key、token、access key、secret key 等同类密钥必须用单引号包起来 |  |
| 特殊字符风险 | 密钥包含 `$`、`!`、空格、反引号、`&`、`|`、`;`、`<`、`>` 时，未加单引号会被 Shell 展开或截断 |  |

`config/.<profile>.env` 中同类密钥必须按以下格式填写：

```bash
NACOS_PASSWORD='<从运维密钥获取>'
SPRING_RABBITMQ_PASSWORD='<从运维密钥获取>'
V1_CARDAPI_JWT_SECRET='<从运维密钥获取>'
MYSQL_PASSWORD='<从运维密钥获取>'
CARD_SHOP_REDIS_PASSWORD='<从运维密钥获取>'
```

非密钥变量可以按普通形式填写，例如：

```bash
APP_PROFILE=dev
SERVER_PORT=10080
SPRING_RABBITMQ_PORT=5672
```

## 3. 启停和健康检查

| 操作 | 开发/测试环境 | 生产环境 |
| --- | --- | --- |
| 进入目录 | `cd /data/apps/cardshop-trade-engine/cardshop-trade-engine-0.1.0-SNAPSHOT` |  |
| 查看状态 | `./bin/start.sh status dev` |  |
| 启动服务 | `./bin/start.sh start dev` |  |
| 停止服务 | `./bin/start.sh stop dev` |  |
| 重启服务 | `./bin/start.sh restart dev` |  |
| 查看启动日志 | `tail -n 200 logs/cardshop-trade-engine-dev.out` |  |
| Liveness 检查 | `curl -sS http://127.0.0.1:10080/actuator/health/liveness` |  |
| Readiness 检查 | `curl -sS http://127.0.0.1:10080/actuator/health/readiness` |  |
| Prometheus 检查 | `curl -sS http://127.0.0.1:10080/actuator/prometheus` |  |

启动前重点确认：

- `config/.dev.env` 中 `APP_PROFILE=dev`，且命令参数也使用 `dev`。
- `CARD_SHOP_TRADE_JAVA_HOME` 指向 JDK 21，或服务器默认 `JAVA_HOME` 已是 JDK 21。
- Nacos、RabbitMQ、V1 JWT secret 等启动必需密钥已经存在，且同类密钥在 `.env` 中使用单引号。
- MySQL、Redis、灰度名单、业务开关、供应商配置等运行配置应从 Nacos 或部署密钥读取，不应写入部署包模板。

开发/测试环境关键配置参考：

```yaml
spring:
  datasource:
    url: ${MYSQL_URL}
    username: ${MYSQL_USER}
    password: ${MYSQL_PASSWORD}
  data:
    redis:
      host: ${CARD_SHOP_REDIS_HOST}
      port: ${CARD_SHOP_REDIS_PORT:6379}
      database: ${CARD_SHOP_REDIS_DATABASE:15}
      password: ${CARD_SHOP_REDIS_PASSWORD}
  rabbitmq:
    virtual-host: cardshop-trade-dev

trade:
  engine:
    redis:
      write-enabled: true
      wait-replicas: 0
      wait-timeout-ms: 100
```

`wait-replicas=0` 是开发/测试环境为了先跑通单笔 happy path 的临时策略。后续切换到可确认副本的 Redis 环境后，需要重新评估恢复为设计值。

## 8. RabbitMQ 配置

| 项目 | 开发/测试环境 | 生产环境 |
| --- | --- | --- |
| 管理控制台 | `http://47.100.11.188:15672` |  |
| RabbitMQ 版本 | `3.8.8` |  |
| AMQP Host | `47.100.11.188` |  |
| AMQP Port | `5672` |  |
| vhost | `cardshop-trade-dev` |  |
| RabbitMQ 用户 | `admin_cardshop` |  |
| 密码 | 不落盘，从运维密钥、环境变量或部署平台变量获取 |  |
| 权限 | `configure=.*`，`write=.*`，`read=.*` |  |
| 主队列 | `recharge.persist.mysql.queue`，quorum queue |  |
| retry queue | `recharge.persist.mysql.retry.queue`，classic queue |  |
| DLQ | `recharge.persist.mysql.dlq` |  |

说明：

- 不建议使用默认 `/` vhost 进行本项目联调；当前项目应使用 `cardshop-trade-dev`。
- RabbitMQ `3.8.8` 对 quorum queue 不接受 `x-message-ttl`，因此 retry queue 使用 classic queue。
- 如果控制台连接数为 `0`，先结合应用启动日志和 `/actuator/prometheus` 判断应用是否真的创建了 AMQP connection，再排查 vhost 或权限。
- 密码不得写入 Git、Markdown、Nacos 模板、测试配置或日志。

RabbitMQ 连接指标检查：

```bash
curl -sS http://127.0.0.1:10080/actuator/prometheus | grep -E 'rabbitmq_connections|rabbitmq_channels'
```

管理 API vhost 创建模板：

```bash
export RABBITMQ_MGMT_URL='http://47.100.11.188:15672'
export RABBITMQ_USERNAME='admin_cardshop'
export RABBITMQ_PASSWORD='<从运维密钥获取>'
export RABBITMQ_VHOST='cardshop-trade-dev'

curl -u "${RABBITMQ_USERNAME}:${RABBITMQ_PASSWORD}" \
  -X PUT "${RABBITMQ_MGMT_URL}/api/vhosts/${RABBITMQ_VHOST}"

curl -u "${RABBITMQ_USERNAME}:${RABBITMQ_PASSWORD}" \
  -H 'content-type: application/json' \
  -X PUT "${RABBITMQ_MGMT_URL}/api/permissions/${RABBITMQ_VHOST}/${RABBITMQ_USERNAME}" \
  --data '{"configure":".*","write":".*","read":".*"}'
```

## 9. 部署后验证

| 步骤 | 开发/测试环境 | 生产环境 |
| --- | --- | --- |
| 1. 检查进程 | `./bin/start.sh status dev` 返回 running |  |
| 2. 检查健康 | liveness/readiness 均返回 `UP` |  |
| 3. 检查日志 | 启动日志无 Nacos、MySQL、Redis、RabbitMQ 连接错误 |  |
| 4. 检查 RabbitMQ | Prometheus 中 `rabbitmq_connections{name="rabbit"}` 大于 `0` |  |
| 5. 检查 Redis WAIT 策略 | Nacos dev 中 `trade.engine.redis.wait-replicas=0` |  |
| 6. 跑测试单 | 使用灰度商户和测试订单前缀发起一笔小额测试单 |  |
| 7. 核对 Redis | 订单快照最终进入 `DB_PERSISTED`，pending 被清理 |  |
| 8. 核对 RabbitMQ | 发布、消费指标各增加 `1`，主队列无异常堆积 |  |
| 9. 核对 MySQL | `mc_order`、`recharge_order_ext`、`mc_depart_record`、`recharge_outbox` 均落库 |  |
| 10. 记录结果 | 将订单号、时间、健康检查、关键指标和异常处理结果补充到集成测试记录 |  |

如果 `./bin/start.sh status dev` 显示未运行，按以下顺序处理：

1. 查看 `logs/cardshop-trade-engine-dev.out` 是否存在启动失败堆栈。
2. 确认 `config/.dev.env` 中所有必填变量已配置，密钥已使用单引号。
3. 确认 JDK 21 可用，端口 `10080` 未被占用。
4. 执行 `./bin/start.sh start dev`。
5. 重新检查 liveness、readiness、RabbitMQ 指标和单笔测试单。
