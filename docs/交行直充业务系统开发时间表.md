# 交行直充业务系统开发时间表

## 1. 压期说明

本时间表面向新建 `cardshop-trade-engine` 服务，开发范围以《交行直充业务系统详细设计》和《交行直充业务系统高可用方案设计》为准。

目标周期压缩为 2 周内完成第一版可上线能力，按 14 个自然日排期。该排期不是完整舒适开发周期，而是最小可上线版本排期，要求开发、测试、运维并行推进。

排期默认假设：

1.  Redis Sentinel、RabbitMQ Quorum Queue、MySQL 测试库、Nacos、XXL-Job 在第 1 天可准备完成。
    
2.  首期只实现 `/v1/cardapi` 直充链路，不迁移 v2/v5/其他交易类型。
    
3.  首期供应商派单优先覆盖当前交行直充涉及的核心渠道，其余渠道保留扩展接口。
    
4.  当前阶段直充产品不校验商品限额和库存。
    
5.  不开发新的后台管理页面，排障依赖日志、数据库、Prometheus 指标和临时诊断接口。

## 4. 两周内必须实现的功能

以下能力不能后置，否则不允许灰度上线：

1.  `/v1/cardapi` 无侵入路由和旧系统代理。
    
2.  token、SM4、SM3、timestamp、nonce、request\_hash。
    
3.  Redis Lua 幂等、余额预扣、`repairing_lock`、pending、org\_index。
    
4.  Redis `WAIT`、cancel、`recharge_accept_anomaly`。
    
5.  RabbitMQ publisher confirm、publish breaker、MQ snapshot。
    
6.  MySQL 异步落库和 `recharge_order_ext` 版本前进。
    
7.  Redis pending 补投和 Consumer 并发幂等。
    
8.  outbox 抢占、供应商派单、回调重试。
    
9.  关键监控告警和回滚方案。
    

## 5. 后续要补齐的功能

为保证 2 周内交付，以下内容可作为首期灰度后的增强项：

1.  完整后台排障页面，首期使用日志、SQL、Prometheus 和临时诊断接口。
    
2.  全量供应商通道适配，首期只做交行直充涉及的核心通道。
    
3.  自动化财务报表，首期只保证余额流水、刷账 outbox 和对账告警。
