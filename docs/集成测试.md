### 3. 真实名创协议实现核查

已具备的通用能力包括：按选定子商品/渠道派单、供应商流水、outbox CAS 抢占与恢复、派单结果未知转查单、查单退避、订单终态、余额释放及商户回调。相关 SUP-001 至 SUP-004 历史用例使用 mock 或合成样本，不构成真实名创 API 验收。

当前 `TradeEngineInfrastructureConfiguration#rechargeSupplierGatewayPort` 仅装配 `HttpRechargeSupplierGatewayAdapter`，未发现 MINISO 专属 Gateway。对照旧仓库 `MINISOSupplierTradeServiceImpl`、`MCUtils` 和 `HttpUtils#sendMcPost`，缺口如下：

- 鉴权：旧协议携带 tenant/tripartite/version/nonce/time/sign 请求头，并由 MCUtils 生成名创签名；新通用适配器只设置 Content-Type，没有对应鉴权实现和渠道密钥配置。

- 查单请求：旧协议发送 `orderNo`；新适配器发送通用订单字段，缺少名创请求转换及鉴权。
- 响应归一化：新适配器把 `code=200/0` 或通用成功状态直接作为成功，未校验名创 data 中明细完整性、数量、couponCode/endTime；未识别的 2xx JSON 业务码默认判 FAILED，缺少渠道失败码白名单与未知结果分类，直接连真实 API 可能错误成功或错误退款。

### 3. 根因分析

#### 3.1 `recharge_order_ext` 长尾（已部分治理）

- phase 计时对应 `insertExtBatchOrUpdatePersistState`（multi-row INSERT…ODKU）。
- 非表扫描问题（当时仅千行级）；主因是双唯一键争用 + 低基数二级索引 `idx_ext_persist_status(persist_status, updated_at)` 右端热点。
- 代码侧无按 `(persist_status, updated_at)` 扫描的正式路径；补偿靠 Redis pending。
- **已落地**：Liquibase `0016` DROP 该索引；设计文档已同步。
- **效果**：ext phase 明显下降，但**总落库吞吐几乎不变**（瓶颈转移到 outbox）。

#### 3.2 `Sleep` + 长事务（已澄清）

- 曾观察到 `testuser` 连接 `Sleep` 但仍 `RUNNING`、已改 60/80 行、age 达数十秒。
- `jstack` 对齐结论：**不是连接池泄漏，也不是 `@Transactional` 失效**（栈含 `TransactionInterceptor`）。
- 8 个 persist Listener 同时卡在 MySQL socket read（各表 insert batch）；长事务 = 多 phase 锁等待之和。
- `Sleep` 多为语句间隙/采样表象；真正阻塞在 SQL 内。

#### 3.3 履约 timer 热路径（本轮最大发现）

- XXL 的 `rechargeSupplierDispatchJob` / `rechargeSupplierQueryJob` / `rechargeOutboxPublishJob` **早已停止**，但仍见大量 `recharge-dispatch-worker-*`。
- 根因：`trade.engine.fulfillment.timer-enabled=true` 且 `outbox-parallelism=32` → **32 timer + 32 worker** 与落库批写抢 `recharge_dispatch_outbox`。
- 采样时曾见 **32 个 worker 同时阻塞在 MySQL socket**；`dispatch.timer.worker.rejected` 累计数百。

#### 3.4 共享 RDS 噪声

- 交易表行锁未被别库直接锁死；INNODB STATUS 仍可见同实例 `aifuli-mall-test.product_spu` 等更新噪声，放大整体抖动。

### 7. 结论

1. **入口同步链路健康**（百级 QPS、毫秒级延迟）；容量短板在异步落库。
2. **删除 `idx_ext_persist_status` 正确且有效于 ext phase**，但不能单独解决总吞吐。
3. **最大杠杆是关闭履约 timer（或显著降低 `outbox-parallelism`）**：避免 32 并行 worker 与 persist 批写同表互锁；XXL 三 Job 停用并不能替代关 timer。
4. **长事务是锁等待结果**，不是独立泄漏；降 persist 并发可缩短 trx_age，但在 timer ON 时几乎不提升吞吐。
5. **timer OFF + consumers=8** 时落库约 **40–50/s**，仍追不上 ~190 入口；下一轮可在 `concurrency=8/max=16`、timer 保持 false 下复压，观察是否继续抬升，并警惕再次引入 timer 后的回退。
6. 共享 RDS 上其它库写负载仍是背景噪声，复压时需一并观察。
