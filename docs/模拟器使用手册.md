# 交易引擎模拟器使用手册

本文档说明 `cardshop-trade-engine-simulator` 打包产物中的两个工具用法。二者共用同一个 jar / 启动脚本，通过 `--mode` 区分角色：

| 工具 | `--mode` | 角色 | 需要商户密钥 |
| --- | --- | --- | --- |
| **工具一：A39 业务模拟器** | `scenario`（默认）/ `load` | 模拟商户侧调用交易引擎 V1 接口 | 是（`app-secret` / `aes-key`） |
| **工具二：供应商 HTTP Mock** | `supplier-mock` | 模拟供应商下单/查单 HTTP 服务，供引擎 Outbox 联调 | 否 |

设计参考：

- `docs/superpowers/specs/2026-07-13-a39-business-simulator-design.md`
- `docs/superpowers/specs/2026-07-15-a39-simulator-load-test-design.md`
- `docs/superpowers/specs/2026-07-20-supplier-mock-design.md`

适用环境：仅限 **dev / test / 联调**。禁止对生产真实商户或生产真实供应商放量。

---

## 1. 快速对照

| 你想做的事 | 启动哪个 | 典型命令 |
| --- | --- | --- |
| 单笔联调：token → 下单 → 查单 → 收回调 | 工具一 `scenario` | `./bin/run-a39-simulator.sh --mode scenario --notify-url ...` |
| 压创建订单入口吞吐 | 工具一 `load` | `./bin/run-a39-simulator.sh --mode load --concurrency 10 --total-orders 200` |
| 给引擎 Outbox 提供假供应商 | 工具二 `supplier-mock` | `./bin/run-a39-simulator.sh --mode=supplier-mock --port=18082` |
| 压测 + 假供应商闭环 | 同机双进程：工具二 + 工具一 `load` | 先起 mock，再起 load |

同机可并行：一个进程跑 A39，另一个进程跑 `supplier-mock`（端口不要冲突）。

## 2. 打包与部署

### 2.1 本地打包

需要 **JDK 21**：

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"

./scripts/package-a39-simulator.sh
```

产物：`dist/a39-business-simulator-<version>.zip`

```text
a39-business-simulator-<version>/
  app/cardshop-trade-engine-simulator-<version>.jar
  bin/run-a39-simulator.sh
  config/a39-simulator.env.example
```

说明：该模块**不**进入主服务 `./scripts/package.sh` 发布包。

### 2.2 部署机解压

```bash
cd /data/apps/cardshop-trade-engine   # 或实际部署目录
unzip a39-business-simulator-<version>.zip
cd a39-business-simulator-<version>

cp config/a39-simulator.env.example config/a39-simulator.env
chmod 600 config/a39-simulator.env
vi config/a39-simulator.env
```

### 2.3 启动脚本行为

`bin/run-a39-simulator.sh` 会：

1. 若存在则 `source config/a39-simulator.env`
2. 探测 JDK 21（优先 `CARD_SHOP_TRADE_JAVA_HOME`，其次 `JAVA_HOME`，再试常见路径）
3. 执行 `java -jar app/cardshop-trade-engine-simulator-*.jar` 并透传命令行参数

**优先级：** 命令行参数 > 环境变量（含 `.env`）> 内置默认值。

### 2.4 帮助

```bash
./bin/run-a39-simulator.sh --help
./bin/run-a39-simulator.sh --help --mode supplier-mock
```

### 2.5 源码直接跑（开发机）

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home

# 工具一
A39_APP_SECRET='***' A39_AES_KEY='***' \
mvn -f cardshop-trade-engine-simulator/pom.xml exec:java \
  -Dexec.args="--mode scenario --notify-url http://127.0.0.1:19039/callback/order"

# 工具二
mvn -f cardshop-trade-engine-simulator/pom.xml exec:java \
  -Dexec.args="--mode supplier-mock --port 18082"
```

## 3. 工具一：A39 业务模拟器

### 3.1 定位

按 `docs/交行直充接口技术文档-V1.1.docx` 模拟机构侧行为：

1. `POST /v1/cardapi/auth/getToken`
2. SM3 签名（可按配置对订单/查单体做 SM4）
3. `POST /v1/cardapi/order/createRechargeOrder`
4. （`scenario`）按条件查单 `getRechargeOrder`，并本机接收商户回调

`--product-id` 传的是 MySQL `mc_depart_product.parent_id`（父产品号），不是最终派单子商品号。例如 test188 MINISO 样本常用父号 `80100022`（子号多为 `80100023`）。

### 3.2 安全边界

| 项 | 要求 |
| --- | --- |
| `A39_APP_SECRET` / `A39_AES_KEY` | `scenario` / `load` **必填**；写入本地 `config/a39-simulator.env`，勿提交 Git，勿写进 shell 历史 |
| 目标环境 | 仅测试商户 / 测试商品 |
| `load` | 禁止对准生产；供应商应指向安全 mock |

`config/a39-simulator.env` 最小示例：

```bash
export CARD_SHOP_TRADE_JAVA_HOME='/opt/java/jdk-21.0.11'

export A39_APP_SECRET='真实密钥'
export A39_AES_KEY='真实密钥'

export A39_BASE_URL='http://apitest.kalaiwang.com'
export A39_APP_ID='A35cecjXS7lZ1W30NMN'
export A39_PRODUCT_ID='80100022'
export A39_ACCOUNT='18186222336'
export A39_REQUEST_SM4='true'
```

### 3.3 模式 A：`scenario`（单笔联调，默认）

**流程：** 起本机回调接收器 → getToken → 下单 → 按业务码决定是否查单 → 等待回调。

```bash
./bin/run-a39-simulator.sh \
  --mode scenario \
  --out-order-sn A39TEST$(date +%Y%m%d%H%M%S) \
  --notify-url http://127.0.0.1:19039/callback/order \
  --query-attempts 3 \
  --query-interval 30s \
  --callback-wait 10m
```

**查单决策（摘要）：**

- 下单业务码 `200` / `510`：进入查单轮询
- 其它业务失败：默认不查
- 查到终态 `6/11/12` 停止；处理中 `0/2/13` 或查询失败则按间隔重试直至次数耗尽

**`notify_url` 要点：**

- `scenario` **必须非空**
- URL 必须是**被测交易引擎能访问到**的地址
- `--callback-bind-host` / `--callback-port` 只决定本机监听；发给平台的是完整 `--notify-url`
- 模拟器与引擎不同机时，不要用 `127.0.0.1`，改用内网 IP / nginx / 隧道

| 场景 | 推荐 `--notify-url` |
| --- | --- |
| 与引擎同机 | `http://127.0.0.1:19039/callback/order` |
| 同网段另一台 | `http://<模拟器内网IP>:19039/callback/order` |
| 经 nginx | `http://<nginx>/a39/callback/order`（反代到模拟器端口） |

**日志关键字：**

- `[A39][HTTP][request]`：脱敏 curl（`app_secret` / `Authorization` 不输出明文）
- `[A39][HTTP][response]`：HTTP 状态与响应体
- `[A39][ORDER][status-change]`：查单状态变化

成功退出码一般为 `0`。

### 3.4 模式 B：`load`（下单入口压测）

**流程：** 获取一次 token → 按并发创建订单 → 结束并打印报告。

**不做：** 查单、启动回调接收器、等待回调。  
**强制：** `notify_url` 为空（显式传非空会拒绝启动），避免制造回调任务噪声。

基线：

```bash
./bin/run-a39-simulator.sh \
  --mode load \
  --concurrency 10 \
  --total-orders 200 \
  --request-timeout 10s \
  --out-order-prefix PERF-A39-$(date +%Y%m%d%H%M%S)
```

按时长 + 目标 QPS（适合持续压测窗口）：

```bash
./bin/run-a39-simulator.sh \
  --mode load \
  --concurrency 10 \
  --duration 10m \
  --rate 50 \
  --request-timeout 10s \
  --out-order-prefix PERF-A39-$(date +%Y%m%d%H%M%S)
```

**压测语义：**

- 任意时刻最多 `concurrency` 个在途下单请求
- `--rate > 0`：按约 `1/rate` 秒节流提交；`0` 表示打满并发
- `--duration > 0`：窗口截止后停止新提交并排空在途；需配合 `--rate` 或 `--total-orders`
- 默认成功业务码：`200`、`510`（可用 `--expected-create-codes` 覆盖）
- 每笔独立 `out_order_sn` / `nonce_str` / `timestamp` / `sign`
- 退出码 `0`：全部完成且无失败；否则非 `0`

**报告字段（摘要）：**  
`completed/successful/failed`、各业务码计数、`minMs/maxMs/p50/p95/p99`、`qps`、`exitCode`，以及客户端耗时拆分 `timing.prepare|untilHeaders|bodyRead|parse|clientTotal`。

### 3.6 工具一常见排障

| 现象 | 排查 |
| --- | --- |
| `UnsupportedClassVersionError` … `65.0` | 实际在跑 Java 8；安装 JDK 21 并设 `CARD_SHOP_TRADE_JAVA_HOME` |
| `getToken failed: code=401` | `app_id/app_secret` 与目标环境商户不匹配，或 env 仍是 `***` |
| `code=500, msg=商户配置缺失或版本不一致` | Redis 缺商户/商品配置；检查 `merchant:config` 与 `product:<selected_product_id>:config` |
| 收不到回调 | `--notify-url` 从引擎视角不可达；核对 IP/防火墙/nginx |
| `load` 启动拒绝非空 notify | 按设计强制空回调；去掉 `--notify-url` |

## 4. 工具二：供应商 HTTP Mock

### 4.1 定位

为交易引擎 `HttpRechargeSupplierGatewayAdapter` 提供本地假供应商：

- 下单立即 HTTP 200 + `status=PROCESSING`
- 在配置的随机延迟窗口后，查单返回预定终态 `SUCCESS` 或 `FAILED`
- 响应 JSON 字段：`status` / `code` / `message` / `supplier_order_id`

**不需要** `app-secret` / `aes-key`。进程常驻，Ctrl+C 结束。

### 4.2 启动

```bash
./bin/run-a39-simulator.sh \
  --mode=supplier-mock \
  --bind-host=0.0.0.0 \
  --port=18082 \
  --final-result-delay-ms-min=1200 \
  --final-result-delay-ms-max=9800 \
  --success-rate=0.95
```

后台示例（部署机）：

```bash
nohup ./bin/run-a39-simulator.sh \
  --mode=supplier-mock \
  --bind-host=0.0.0.0 \
  --port=18082 \
  > /tmp/supplier-mock.log 2>&1 &
```

### 4.3 监听路径（同一逻辑，两套路径）

| 用途 | 通用路径 | MINISO 兼容路径 |
| --- | --- | --- |
| 下单 | `POST /supplier/dispatch` | `POST /tripartite/coupon/batchGrandCoupon` |
| 查单 | `POST /supplier/query` | `POST /tripartite/coupon/queryGrand` |

请求体订单身份：优先 `order_id`，缺失则用 `supplier_request_id`（与引擎 Gateway 下发字段一致）。

### 4.4 状态机

1. **首次下单：** 立刻返回 `PROCESSING`（code `202`）；为该订单抽样  
   - `readyAt = now + U[min, max]`  
   - 终态：以 `success-rate` 概率为 `SUCCESS`（code `0`），否则 `FAILED`（code `E_MOCK_FAIL`）
2. **查单：**  
   - 未知订单 → `FAILED` / `E_MOCK_NOT_FOUND`  
   - `now < readyAt` → 仍 `PROCESSING`  
   - `now >= readyAt` → 返回下单时已定好的终态
3. **重复下单：** 幂等，不重置 `readyAt`/终态

订单状态仅存**进程内存**；重启 mock 即清空。首期无作废（invalid）接口。

### 4.5 与 Nacos / 引擎对接

在 `cardshop-trade-engine-supplier.yaml`（或等价 DataId）配置，例如：

```yaml
trade:
  engine:
    supplier:
      http-enabled: true
      channels:
        MINISO:
          dispatch-url: http://127.0.0.1:18082/tripartite/coupon/batchGrandCoupon
          query-url: http://127.0.0.1:18082/tripartite/coupon/queryGrand
          timeout-ms: 10000
```

或通用路径：

```yaml
dispatch-url: http://127.0.0.1:18082/supplier/dispatch
query-url: http://127.0.0.1:18082/supplier/query
```

**`127.0.0.1` 警告：**

- 该地址从**每个 trade-engine JVM 所在机器**解析
- mock 必须与发起派单的引擎实例**同机**，或把 URL 改成 mock 所在主机的内网 IP
- pro143 / pro140 / pro120 多实例共用同一 Nacos 时：只在本机起了 mock 的节点能通；其它节点会 `ConnectException`，Outbox 按可重试失败退避

引擎侧 `timeout-ms` 只需覆盖 **HTTP 瞬时回包**（本 mock 下单/查单默认立即响应）。终态等待由引擎 `SUPPLIER_QUERY` outbox 退避完成，应能覆盖 `final-result-delay-ms-max`。

### 4.6 工具二参数表

| 参数 | 环境变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--mode=supplier-mock` | `A39_MODE` | — | 必须为 `supplier-mock` |
| `--bind-host` | `SUPPLIER_MOCK_BIND_HOST` | `0.0.0.0` | 监听地址 |
| `--port` | `SUPPLIER_MOCK_PORT` | `18082` | 监听端口（1–65535） |
| `--final-result-delay-ms-min` | `SUPPLIER_MOCK_FINAL_RESULT_DELAY_MS_MIN` | `1200` | 终态就绪最小延迟（毫秒） |
| `--final-result-delay-ms-max` | `SUPPLIER_MOCK_FINAL_RESULT_DELAY_MS_MAX` | `9800` | 终态就绪最大延迟（毫秒），须 ≥ min |
| `--success-rate` | `SUPPLIER_MOCK_SUCCESS_RATE` | `1.0` | 新订单终态成功概率 `[0.0, 1.0]` |

### 4.7 手工冒烟（可选）

```bash
# 下单
curl -s -X POST http://127.0.0.1:18082/supplier/dispatch \
  -H 'Content-Type: application/json' \
  -d '{"order_id":"ORDER-1","supplier_request_id":"dispatch-ORDER-1","account":"13800138000"}'

# 立即查单（通常仍为 PROCESSING）
curl -s -X POST http://127.0.0.1:18082/supplier/query \
  -H 'Content-Type: application/json' \
  -d '{"order_id":"ORDER-1","supplier_request_id":"supplier-query-ORDER-1"}'
```

把 delay 配成 `0/0` 时，首次下单仍返回 `PROCESSING`，紧接着查单即可拿到终态。

### 4.8 工具二常见排障

| 现象 | 排查 |
| --- | --- |
| 引擎日志 `ConnectException` 打 `127.0.0.1:18082` | 本机未起 mock，或 Nacos 仍指向本机但引擎在其它机器 |
| 一直 PROCESSING、不出终态 | delay 窗口过大，或引擎未跑 `SUPPLIER_QUERY` / Outbox Job |
| 端口占用 | 换 `--port`，并同步改 Nacos URL |
| 重启后订单“丢失” | 内存态；属预期 |

## 5. 推荐联调组合

### 5.1 pro143 / test188：假供应商 + 单笔联调

终端 1：

```bash
./bin/run-a39-simulator.sh --mode=supplier-mock --bind-host=0.0.0.0 --port=18082
```

确认 Nacos 供应商 URL 指向该机 `18082`，引擎已加载配置。

终端 2（同机或可达引擎的机器）：

```bash
./bin/run-a39-simulator.sh \
  --mode scenario \
  --notify-url http://<对引擎可达的回调地址>:19039/callback/order
```

### 5.2 压测入口（建议配合 mock）

1. 起 `supplier-mock`（避免压真实供应商）
2. 确认 `A39_PRODUCT_ID`、商户密钥、余额/商品 Redis 基线就绪
3. 跑 `load`，记录报告到 `docs/集成测试.md`

### 5.3 端口与进程对照

| 进程 | 默认端口 | 谁连它 |
| --- | --- | --- |
| 供应商 mock | `18082` | 交易引擎 Outbox Worker |
| A39 回调接收器（scenario） | `19039` | 交易引擎商户回调发送方 |
| 交易引擎 HTTP | 按环境（如 8080/10081） | A39 模拟器作为客户端 |

## 6. 明确不做 / 禁止事项

- 不把模拟器打进主服务生产包
- 不把真实 `app_secret` / `aesKey` 提交仓库
- `load` / `supplier-mock` 不对准生产流量
- `supplier-mock` 不做作废接口、不做跨进程状态持久化
- 同一进程不能同时跑 A39 与 supplier-mock（请开两个进程）
