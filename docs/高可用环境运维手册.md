# cardshop-trade-engine 高可用环境运维手册

> 更新时间：2026-07-16  
> 适用范围：`pro143`、`pro197`、`pro120` 三节点 trade-engine 专用 Redis Sentinel、RabbitMQ 集群、Docker Compose 中间件运维，以及 `pro143`、`pro140`、`pro120` 三节点应用运维。
> 关联文档：`docs/高可用环境部署方案.md`、`docs/交行直充业务系统高可用方案设计.md`、`docs/交行直充业务系统详细设计.md`。

## 1. 运维总则

1. 三台中间件统一由 Docker Compose 管理，目录固定为 `/data/trade-engine/deploy`。
2. `.env`、RabbitMQ cookie、Redis/RabbitMQ 密码只允许保存在服务器受限文件或运维密钥系统，不写入 Git、Markdown、日志、命令历史和截图。
3. 所有变更按滚动方式执行，同一时间只操作一台服务器或一个服务。
4. 禁止执行 `docker compose down -v`，禁止删除 `/data/trade-engine/redis`、`/data/trade-engine/sentinel`、`/data/trade-engine/rabbitmq`。
5. RabbitMQ 重建前必须确认 Compose 中存在 `extra_hosts`，否则节点名解析异常会导致集群视图不完整。
6. pro120 上旧 RabbitMQ 仍运行在默认端口，任何操作都只针对 `trade-rabbitmq`、`trade-redis`、`trade-redis-sentinel`。

## 3. 每日巡检

### 3.1 三台 Compose 状态

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h ====="
  ssh "$h" 'cd /data/trade-engine/deploy && docker compose config --quiet && docker compose ps'
done
```

预期：

1. `docker compose config --quiet` 无输出且退出码为 0。
2. `trade-rabbitmq`、`trade-redis`、`trade-redis-sentinel` 均为 `Up`。
3. 不应出现 `Restarting`、`Exited`、`Created` 长时间不变。

### 3.2 服务器资源

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h ====="
  ssh "$h" 'hostname; uptime; free -h; df -h / /data 2>/dev/null || df -h /; docker stats --no-stream trade-rabbitmq trade-redis trade-redis-sentinel'
done
```

重点关注：

1. pro197 可用内存低于 2G 时，先检查旧业务、日志、RabbitMQ 队列堆积和 Redis AOF rewrite，
   再评估 RabbitMQ/Redis 水位；pro197 不部署 app，不能通过停止 app 释放资源。
2. `/data` 或 `/` 使用率超过 80% 需要清理日志和检查 RabbitMQ 队列堆积。
3. Redis `maxmemory` 不能等于容器内存限制，需要给 AOF rewrite 和复制 backlog 留余量。

### 3.3 RabbitMQ 集群

```bash
ssh pro143 'docker exec trade-rabbitmq getent hosts rmq-pro120 rmq-pro143 rmq-pro197'
ssh pro143 'docker exec trade-rabbitmq rabbitmqctl cluster_status'
ssh pro143 'docker exec trade-rabbitmq rabbitmq-diagnostics erlang_version'
ssh pro143 'docker exec trade-rabbitmq rabbitmqctl version'
```

预期：

1. 三个 `rmq-*` 主机名均能解析到内网 IP。
2. `Disk Nodes` 和 `Running Nodes` 均包含 `rabbit@rmq-pro120`、`rabbit@rmq-pro143`、`rabbit@rmq-pro197`。
3. 三节点版本一致：RabbitMQ `4.3.x`，Erlang/OTP `27.x`。
4. `Alarms` 为 `(none)`，`Network Partitions` 为 `(none)`。

队列巡检：

```bash
ssh pro143 'docker exec trade-rabbitmq rabbitmqctl list_queues -p cardshop-trade-prod name type durable messages_ready messages_unacknowledged'
ssh pro143 'docker exec trade-rabbitmq rabbitmqctl list_policies -p cardshop-trade-prod'
```

主队列和 DLQ 应为 Quorum Queue；retry queue 是 classic durable queue + TTL + DLX，不要用全局策略强制所有队列为 quorum。

### 3.4 Redis 与 Sentinel

不要打印密码。以下命令在各 Redis 所在服务器本机读取 `requirepass` 后仅传给 `redis-cli`：

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h redis ====="
  ssh "$h" '
    LOCAL_IP=$(hostname -I | awk "{print \$1}")
    REDIS_PASS=$(awk "/^requirepass /{print \$2; exit}" /data/trade-engine/redis/conf/redis.conf)
    docker exec -e REDISCLI_AUTH="$REDIS_PASS" trade-redis \
      redis-cli -h "$LOCAL_IP" -p 6380 info replication |
      grep -E "role:|master_host:|master_link_status:|connected_slaves:|slave[0-9]:"
  '
done
```

Sentinel master 视图：

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h sentinel ====="
  ssh "$h" '
    LOCAL_IP=$(hostname -I | awk "{print \$1}")
    docker exec trade-redis-sentinel redis-cli -h "$LOCAL_IP" -p 26380 \
      sentinel get-master-addr-by-name trade-engine-master
  '
done
```

预期：

1. 当前 master 为 `172.19.64.105:6380`。
2. pro197/pro120 为 replica，`master_link_status:up`。
3. 三台 Sentinel 返回同一个 master 地址。
4. master 上 `connected_slaves:2`。

Redis 副本确认：

```bash
ssh pro143 '
  REDIS_PASS=$(awk "/^requirepass /{print \$2; exit}" /data/trade-engine/redis/conf/redis.conf)
  docker exec -e REDISCLI_AUTH="$REDIS_PASS" trade-redis \
    redis-cli -h 172.19.64.105 -p 6380 WAIT 1 100
'
```

预期返回大于等于 `1`。当前两副本都在线时通常返回 `2`。

### 3.5 应用与入口

应用部署包位置以实际发布目录为准。若使用项目标准启动脚本，巡检口径如下：

```bash
for h in pro143 pro140 pro120; do
  echo "===== $h app ====="
  ssh "$h" 'curl -fsS http://127.0.0.1:10080/actuator/health/readiness || true'
done
```

pro197 Nginx 入口：

```bash
ssh pro197 'nginx -t'
ssh pro197 'curl -fsS http://127.0.0.1/actuator/health/readiness || true'
```

如果应用还未正式接流，Nacos 中 `trade.engine.redis.write-enabled` 应保持 `false`。

### 3.6 应用启动前检查

启动 `prod` 应用前，先确认 Nacos 四个 DataId 均可读。以下命令只输出状态码和字节数，
不打印配置内容：

```bash
ssh pro143 '
  set -e
  APP_DIR=/data/.cardshop/apps/cardshop-trade-engine-0.1.0-SNAPSHOT
  set -a
  . "$APP_DIR/config/.prod.env"
  set +a
  python3 - << "PY"
import json, os, urllib.error, urllib.parse, urllib.request
base = "http://" + os.environ["NACOS_SERVER_ADDR"] + "/nacos"
login = urllib.parse.urlencode({
    "username": os.environ["NACOS_USERNAME"],
    "password": os.environ["NACOS_PASSWORD"],
}).encode()
with urllib.request.urlopen(base + "/v1/auth/login", data=login, timeout=8) as r:
    token = json.loads(r.read().decode()).get("accessToken", "")
for data_id in [
    "cardshop-trade-engine-common.yaml",
    "cardshop-trade-engine-prod.yaml",
    "cardshop-trade-engine-supplier.yaml",
    "cardshop-trade-engine-risk.yaml",
]:
    qs = urllib.parse.urlencode({
        "dataId": data_id,
        "group": os.environ["NACOS_GROUP"],
        "tenant": os.environ["NACOS_NAMESPACE"],
        "accessToken": token,
    })
    try:
        with urllib.request.urlopen(base + "/v1/cs/configs?" + qs, timeout=8) as r:
            body = r.read()
        print(f"{data_id} http=200 bytes={len(body)}")
    except urllib.error.HTTPError as exc:
        print(f"{data_id} http={exc.code}")
PY
'
```

pro140 应用启动前还要确认安全组或 ACL 已放通到三台中间件端口：

```bash
ssh pro140 '
  for target in \
    172.19.64.105:5673 172.19.64.46:5673 172.19.64.103:5673 \
    172.19.64.105:6380 172.19.64.46:6380 172.19.64.103:6380 \
    172.19.64.105:26380 172.19.64.46:26380 172.19.64.103:26380
  do
    host=${target%:*}
    port=${target##*:}
    timeout 2 bash -lc "</dev/tcp/$host/$port" >/dev/null 2>&1 &&
      echo "$target ok" || echo "$target fail"
  done
'
```

## 4. 常规启停

### 4.1 查看日志

```bash
cd /data/trade-engine/deploy
docker compose logs --tail=200 rabbitmq
docker compose logs --tail=200 redis
docker compose logs --tail=200 redis-sentinel
```

跨三台查看：

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h rabbitmq logs ====="
  ssh "$h" 'cd /data/trade-engine/deploy && docker compose logs --tail=80 rabbitmq'
done
```

### 4.2 启动或恢复中间件

```bash
cd /data/trade-engine/deploy
docker compose up -d
docker compose ps
```

单服务恢复：

```bash
cd /data/trade-engine/deploy
docker compose up -d rabbitmq
docker compose up -d redis
docker compose up -d redis-sentinel
```

### 4.3 滚动重启 RabbitMQ

推荐顺序：`pro197 -> pro120 -> pro143`。

每台执行前先在 pro143 验证三节点健康：

```bash
ssh pro143 'docker exec trade-rabbitmq rabbitmqctl cluster_status'
```

单节点重启：

```bash
ssh pro197 '
  cd /data/trade-engine/deploy &&
  docker compose config --quiet &&
  grep -q "rmq-pro143:172.19.64.105" docker-compose.yml &&
  docker compose restart rabbitmq &&
  docker compose ps rabbitmq
'
```

重启后从 pro143 复核三节点全部回到 `Running Nodes`，再操作下一台。

### 4.4 滚动重启 Redis replica

只重启 pro197/pro120 replica 时：

```bash
ssh pro197 '
  cd /data/trade-engine/deploy &&
  docker compose restart redis &&
  docker compose ps redis
'
```

重启后检查该节点：

```bash
ssh pro197 '
  REDIS_PASS=$(awk "/^requirepass /{print \$2; exit}" /data/trade-engine/redis/conf/redis.conf)
  docker exec -e REDISCLI_AUTH="$REDIS_PASS" trade-redis \
    redis-cli -h 172.19.64.46 -p 6380 info replication |
    grep -E "role:|master_host:|master_link_status:"
'
```

### 4.5 维护 pro143 Redis master

pro143 是当前 Redis master，重启前必须确认两个 replica 在线：

```bash
ssh pro143 '
  REDIS_PASS=$(awk "/^requirepass /{print \$2; exit}" /data/trade-engine/redis/conf/redis.conf)
  docker exec -e REDISCLI_AUTH="$REDIS_PASS" trade-redis \
    redis-cli -h 172.19.64.105 -p 6380 info replication |
    grep -E "role:|connected_slaves:|slave[0-9]:"
'
```

短窗口重建 Redis master：

```bash
ssh pro143 '
  cd /data/trade-engine/deploy &&
  docker stop -t 3 trade-redis &&
  docker rm trade-redis &&
  docker compose up -d redis
'
```

恢复后立即验证：

```bash
for h in pro143 pro197 pro120; do
  ssh "$h" '
    LOCAL_IP=$(hostname -I | awk "{print \$1}")
    docker exec trade-redis-sentinel redis-cli -h "$LOCAL_IP" -p 26380 \
      sentinel get-master-addr-by-name trade-engine-master
  '
done
```

如果 Sentinel 已经选出新 master，不要在业务高峰期手工强制回切；先确认应用通过 Sentinel 正常写入，再安排低峰 failback。

### 4.6 重启 Sentinel

Sentinel 可逐台重启：

```bash
ssh pro197 '
  cd /data/trade-engine/deploy &&
  docker compose restart redis-sentinel &&
  docker compose ps redis-sentinel
'
```

任意时刻至少保留 2 个 Sentinel 在线，避免失去投票多数。

## 5. 变更流程

### 5.1 变更前检查

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h ====="
  ssh "$h" '
    cd /data/trade-engine/deploy &&
    docker compose config --quiet &&
    docker compose ps &&
    stat -c "%a %n" docker-compose.yml .env
  '
done
```

变更前必须确认：

1. `.env` 和 `docker-compose.yml` 权限为 `600`。
2. 不变更 `RABBITMQ_ERLANG_COOKIE`、`RABBITMQ_NODENAME`、RabbitMQ hostname、数据目录。
3. 不把镜像 tag 改成 `latest`。
4. 不改 Redis `masterauth`、`requirepass`、Sentinel master 名，除非有完整密钥轮换方案。

### 5.2 备份配置

```bash
for h in pro143 pro197 pro120; do
  ssh "$h" '
    TS=$(date +%Y%m%d%H%M%S)
    mkdir -p /data/trade-engine/deploy/backup
    tar czf /data/trade-engine/deploy/backup/config-$TS.tgz \
      /data/trade-engine/deploy/docker-compose.yml \
      /data/trade-engine/redis/conf \
      /data/trade-engine/sentinel/conf \
      /data/trade-engine/rabbitmq/conf
    chmod 600 /data/trade-engine/deploy/backup/config-$TS.tgz
  '
done
```

备份包可能包含密钥或认证配置，禁止下载到不受控机器或上传到 Git。

### 5.3 镜像升级

仅在明确变更窗口执行。三台必须使用同一 RabbitMQ patch、同一 Erlang/OTP patch、同一 Redis patch 或 digest。

步骤：

1. 修改三台 `.env` 中的镜像变量，保持版本完全一致。
2. 先在 pro197 执行 `docker compose config --quiet`。
3. 按 `pro197 -> pro120 -> pro143` 滚动 `docker compose up -d --force-recreate <service>`。
4. 每台完成后执行 RabbitMQ/Redis 验证，确认集群恢复后再继续下一台。
5. 最后从 pro143 做完整巡检。

## 6. 故障处理

### 6.1 单个 RabbitMQ 节点离线

现象：

1. `cluster_status` 的 `Running Nodes` 少一个节点。
2. 对应服务器 `trade-rabbitmq` 不是 `Up`。

处理：

```bash
ssh <故障节点> 'cd /data/trade-engine/deploy && docker compose ps rabbitmq && docker compose logs --tail=200 rabbitmq'
ssh <故障节点> 'cd /data/trade-engine/deploy && docker compose up -d rabbitmq'
```

恢复后：

```bash
ssh pro143 'docker exec trade-rabbitmq rabbitmqctl cluster_status'
```

如果节点反复离线，检查磁盘、内存、EPMD `4370`、distribution `25673`、`extra_hosts` 和 Erlang cookie。

### 6.2 RabbitMQ 出现 network partitions

处理原则：

1. 暂停业务写入或保持 `write-enabled=false`。
2. 不要随意 `reset` RabbitMQ 节点。
3. 保存三台 `cluster_status`、`docker logs`、系统时间和网络连通性证据。
4. 优先恢复网络和节点进程，让集群自动收敛。
5. 如果必须人工干预，先评估 Quorum Queue leader、队列堆积和未确认消息。

诊断命令：

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h ====="
  ssh "$h" 'docker exec trade-rabbitmq rabbitmqctl cluster_status'
done
```

### 6.3 Redis replica 断开

现象：

1. master 上 `connected_slaves` 小于 2。
2. replica 上 `master_link_status:down`。

处理：

```bash
ssh <replica节点> '
  cd /data/trade-engine/deploy &&
  docker compose logs --tail=200 redis &&
  docker compose up -d redis
'
```

恢复后确认 replica 追上 master：

```bash
ssh <replica节点> '
  REDIS_PASS=$(awk "/^requirepass /{print \$2; exit}" /data/trade-engine/redis/conf/redis.conf)
  docker exec -e REDISCLI_AUTH="$REDIS_PASS" trade-redis \
    redis-cli -h <replica内网IP> -p 6380 info replication |
    grep -E "role:|master_host:|master_link_status:"
'
```

若两个 replica 都断开，应关闭或保持应用写入开关，避免 Redis 单点写入风险。

### 6.4 Redis master 故障或发生 Sentinel failover

先确认三台 Sentinel 的共同视图：

```bash
for h in pro143 pro197 pro120; do
  echo "===== $h ====="
  ssh "$h" '
    LOCAL_IP=$(hostname -I | awk "{print \$1}")
    docker exec trade-redis-sentinel redis-cli -h "$LOCAL_IP" -p 26380 \
      sentinel get-master-addr-by-name trade-engine-master
  '
done
```

如果 master 已切换：

1. 不要直接编辑 Redis 配置强行回切。
2. 确认应用通过 Sentinel 连接新 master。
3. 检查旧 master 恢复后是否成为 replica。
4. 低峰期再规划是否 failback 到 pro143。
5. 在 `docs/集成测试.md` 或故障记录中记录切换时间、旧 master、新 master、影响窗口和后续处理。

### 6.5 Sentinel 多数不可用

如果只有一个 Sentinel 在线，Redis 当前 master 仍可工作，但自动故障转移能力不足。

处理：

```bash
for h in pro143 pro197 pro120; do
  ssh "$h" 'cd /data/trade-engine/deploy && docker compose up -d redis-sentinel && docker compose ps redis-sentinel'
done
```

恢复后确认三台都返回同一个 master。

### 6.6 pro197 资源紧张

pro197 是容量短板。处理顺序：

1. 先确认是否为日志、RabbitMQ 队列、Redis AOF rewrite 或旧业务进程导致。
2. 如果影响 trade-engine，优先保护 RabbitMQ/Redis 可用性；必要时降低 RabbitMQ 内存水位或清理旧业务资源。
3. 不优先停止 pro197 RabbitMQ/Redis，因为它参与 RabbitMQ quorum 和 Redis 副本确认。
4. 磁盘紧急时先清理应用日志、Docker 日志和无用镜像，不删除 RabbitMQ/Redis 数据目录。

安全清理示例：

```bash
docker system df
docker image prune
journalctl --vacuum-time=7d
```

### 6.7 pro120 误操作风险

pro120 同时有旧 RabbitMQ 和 trade-engine RabbitMQ。操作时必须使用容器名和端口区分：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
ss -lntp | grep -E ':(4369|4370|5672|5673|15672|15673|25672|25673)\b'
```

只能操作：

```text
trade-rabbitmq
trade-redis
trade-redis-sentinel
```

不要停止默认端口上的旧 RabbitMQ 服务。

## 7. 回滚

### 7.1 中间件配置回滚

1. 停止业务写入或保持 `write-enabled=false`。
2. 从 `/data/trade-engine/deploy/backup` 找到变更前配置备份。
3. 仅回滚配置文件，不删除数据目录。
4. 按服务滚动重建。

示例：

```bash
cd /data/trade-engine/deploy
tar tzf backup/config-YYYYMMDDHHMMSS.tgz
```

确认备份内容后再恢复，避免覆盖当前有效密钥。

### 7.2 RabbitMQ 回滚

trade-engine RabbitMQ 使用独立端口和独立目录。需要停止本项目 RabbitMQ 时：

```bash
cd /data/trade-engine/deploy
docker compose stop rabbitmq
```

不要操作 pro120 旧 RabbitMQ。

### 7.3 Redis 回滚

先关闭业务写入，等待 pending 收敛，再按需停止：

```bash
cd /data/trade-engine/deploy
docker compose stop redis redis-sentinel
```

停止前必须记录 Redis master、replica、Sentinel 状态，不能清理 `/data/trade-engine/redis/data`。

```bash
    docker exec trade-redis-sentinel redis-cli -h "$LOCAL_IP" -p 26380 sentinel get-master-addr-by-name trade-engine-master
  '
done
```

## 9. 禁止操作清单

1. 禁止 `docker compose down -v`。
2. 禁止删除 `/data/trade-engine/rabbitmq/data`、`/data/trade-engine/redis/data`、`/data/trade-engine/sentinel/data`。
3. 禁止修改 RabbitMQ Erlang cookie 后直接重启。
4. 禁止修改 RabbitMQ `RABBITMQ_NODENAME`、hostname 或 `extra_hosts` 后直接重启。
5. 禁止把 RabbitMQ/Redis 镜像改成 `latest`。
6. 禁止在 pro120 操作默认端口旧 RabbitMQ 来处理 trade-engine 问题。
7. 禁止把 Redis/RabbitMQ 密码、cookie、Nacos 密码写入文档、Git、日志或截图。
8. 禁止在 RabbitMQ 上设置“所有队列强制 quorum”的全局策略。
