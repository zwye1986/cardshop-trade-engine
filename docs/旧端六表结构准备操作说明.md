# 旧端六表结构准备操作说明

日期：2026-10-28。当前交付仅为本地代码、独立迁移包与隔离演练，不授权生产执行。

## 1. 适用范围

为完整旧端 cardShop-admin 新版本准备六张共享表，解决缺表导致的启动探针失败及后续归属查询缺少结构的问题；不启动新引擎，不开启桥接、不迁移测试业务数据。

唯一入口：`com.cardshop.trade.engine.migration.LegacySchemaPreparation`。它解析正式 master，在内存中只保留原 0005/0013/0020/0021/0022/0023，原 identity/checksum 不变。正式 master 和旧端迁移清单均未修改。

- `preview`：完全离线输出六组原 SQL、身份与 checksum；供评审，不包含执行前校验，不应直接当作上线脚本执行。
- `apply EXPECTED_SCHEMA`：校验连接库名，取得同入口互斥锁，检查初始结构/账本，再执行六组变更并核对结构指纹。
- `verify EXPECTED_SCHEMA`：仅检查六表结构及六组原身份/checksum/EXECUTED；取得并释放会话命名锁，不执行 DDL、账本更新或业务 DML。
- 成功退出码 0；任何拒绝或异常退出码 1。成功信息分别为 `APPLIED`、`NOOP`、`VERIFIED`。

首次只接受六表和六组账本全不存在。重入只接受各一条原 EXECUTED 记录及完整结构匹配；部分完成、同名异构、缺索引/字段、精度损失、错误 checksum、MARK_RAN 或重复账本均停止，不自动修补。

**这是旧端前置准备工具，不是通用引擎迁移工具。** 后续正式全量迁移会继续变更扩展结构，此时本工具可能因结构不同拒绝，不可强行重用或恢复旧指纹。

## 2. 本地构建与离线审阅

构建环境 JDK 21、Maven 3.9+。下面从新引擎仓库根目录执行，不连接数据库：

```bash
mvn -B -pl cardshop-trade-engine-migration package dependency:copy-dependencies \
  -DincludeScope=runtime \
  -DoutputDirectory="$PWD/cardshop-trade-engine-migration/target/legacy-schema-dist/lib"
cp cardshop-trade-engine-migration/target/cardshop-trade-engine-migration-0.1.0-SNAPSHOT.jar \
  cardshop-trade-engine-migration/target/legacy-schema-dist/migration.jar
```

将 `migration.jar` 和 `lib/` 作为整体，另附本说明。运行环境仍需 **Java 21**，不能用旧端 Java 8 执行工具；旧端应用继续使用 Java 8，两者分开。

在迁移包目录执行：

```bash
java -cp 'migration.jar:lib/*' \
  com.cardshop.trade.engine.migration.LegacySchemaPreparation preview > preview.sql
```

运行依赖为 Liquibase 4.29.2、MySQL Connector/J 8.3.0 及其运行时依赖；不含 Spring Boot、Nacos、Redis、MQ 或业务 Worker。随包保留 `SHA256SUMS`，Linux 可用 `sha256sum -c SHA256SUMS`，macOS 用 `shasum -a 256 -c SHA256SUMS`。

## 3. 未来获批后的执行方式（本轮未执行生产）

批准前应重新核对目标主数据源、当前六表/账本、维护窗口、备份恢复点、DDL 权限及其他迁移/业务写入者。预期 schema 校验只能防止库名不符，不能识别同名异实例；主机、端口、实例身份仍须人工核对。命名锁只约束同入口，不替代维护窗口或完整 Liquibase 迁移锁。

通过受控秘密注入提供以下环境变量，不把密码写在命令行、文档或 shell 历史中，不开启 `set -x`：

- `LEGACY_SCHEMA_JDBC_URL`：明确主机、端口、schema 及连接/读取超时的 JDBC URL；生产 TLS 参数遵循现场安全要求，不照搬本地 `useSSL=false`。
- `LEGACY_SCHEMA_USER`、`LEGACY_SCHEMA_PASSWORD`：获批账号凭据。

在迁移包目录显式填写已核对的 schema，再执行：

```bash
java -cp 'migration.jar:lib/*' \
  com.cardshop.trade.engine.migration.LegacySchemaPreparation apply EXPECTED_SCHEMA
java -cp 'migration.jar:lib/*' \
  com.cardshop.trade.engine.migration.LegacySchemaPreparation verify EXPECTED_SCHEMA
```

保留退出码、迁移日志和六条真实 EXECUTED 记录。初次成功后确认六表为空、原账本记录未改、旧主单/流水结构与事实未改。然后才进入另行批准的旧端发布，模式仍为 LEGACY，receive/routing/legacy-notify 三开关 false，桥接 Job 不启用。结构成功不能代替完整应用和业务验收。

DDL 非事务整体原子操作：若中断或后验不符，停止升级，保留现场按实际已提交结构制定前向恢复。禁止自动 DROP、删账本、changelogSync、clearCheckSums 或伪造 MARK_RAN。应用回退不等于回滚共享表。

## 4. 本地演练结果与限制

- MySQL 8.0.28、lower_case_table_names=1、READ-COMMITTED、utf8/utf8_general_ci，回环随机端口，可丢弃 tmpfs 数据；未连接生产。
- 正式六组迁移及精确重入通过；旧拆单重复事实、旧流水不变；六张新表为空。故障与结构漂移拒绝、原身份校验通过。
- 用此前已采集的生产 DDL/26 条迁移元数据建立本地结构副本，未导入生产业务数据；新增六条记录后共 32 条。
- 冻结旧端候选 JAR SHA-256：`e0581dc0aefad0a8baf4f9047aff8414a3655d903ed906c939c8c2b436538b07`。从真实候选类加载桥接配置，Java 8 下补表前复现探针失败、补表后通过；真实 Mapper 在生产字符集组合下验证旧退款候选保留、新引擎归属排除和已核销状态读取。
- 迁移模块最终 17 项测试通过；旧端工作区 Java 8 定向回归 270 项通过，覆盖 MINISO 接收/认证/事务与 HN_CSW 客户端、查单/回调等既有测试。此工作区测试不是冻结 JAR 的完整业务验收。
- 不含完整 RuoYiApplication 启动、真实调度/MQ/Redis联调、供应商/银行调用或生产业务回归。完整 master 的重复键门禁仍存在，不能据此启用新引擎生产接单。
